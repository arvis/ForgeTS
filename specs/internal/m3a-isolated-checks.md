## Acceptance criteria

- Prepare an offline toolchain image from the already approved pinned Node image and exact installed lockfile packages after `npm ci`. Copy only validated regular dependency files and fixed verification assets into a fresh scoped build context; exclude workspace links, credentials, arbitrary repositories and generated target code. No install hooks, Dockerfile RUN instruction or build network access. Record content fingerprint, versions and resulting immutable image ID in trusted local bootstrap metadata. Workers cannot modify it.
- Expose only four versioned check IDs for the approved sample: format (Prettier), lint (ESLint), typecheck (TypeScript) and test (fresh compilation plus an immutable Node test). Reject unknown checks/args/cwd/paths/targets before Docker dispatch. No generated script, shell argument or package configuration can replace the registry. A passing round requires all four fresh results for the same input digest, attempt and toolchain identity.
- Use a distinct M3 worker resource profile: non-root/read-only/no-network/no-capabilities/no-host-mount isolation retained; 512 MiB memory/no extra swap, one CPU, 64 PIDs, 64 MiB no-exec tmpfs. Each check gets a fresh container; capture at most 512 bytes per stdout/stderr stream, eight seconds of child execution and twelve seconds of attached-worker time. Control operations retain fifteen-second limits; cleanup uncertainty blocks further execution. Every container/process namespace is removed even when children detach.
- Record check/command/registry identity, workspace/source/image fingerprints, attempt, exit/signal, timeout/cancellation/resource/truncation/availability/cleanup flags, separate sanitized output and actual durations. Missing/malformed/unavailable/truncated evidence cannot pass. Redaction covers tested credential patterns, not arbitrary secrets.
- Write unhappy-path tests first. Run actual target tools to detect invalid TypeScript, failing unit behavior, lint and format errors, hostile network/credential access, hangs, detached descendants and output flooding. Verify source bytes stay off host execution and resource/cleanup restrictions hold. Preserve M1/M2 checks.
- Run repository verification and actual containment/check tests; record evidence/ADRs/build log and locally commit this spec before durable repair orchestration. The work is on a stacked local `m3/verification` branch because M2 is unmerged; no merge, push, paid call or M4 work is authorized.
