## Acceptance criteria

- Preserve old mock records and API behavior. Add optional bounded execution evidence and an `IMPLEMENTED_UNVERIFIED` terminal state, used only for sandbox-fixture runs with `mergeReady: false`. Real role outputs and worker results cannot be relabeled as M1 simulated checks. Schema and additive migration tests precede changed behavior.
- Reuse PostgreSQL's exclusive owner and single-active-run admission across modes. Bind plan/invocation/tool/artifact hashes to run/workspace/base identities. Persist actual attempts, fixture provenance, requested replacements, observed worker results and a bounded before/after diff. Validate identity/hash/preimage/plan scope before tools; fail closed on persistence/ownership uncertainty.
- Expose a separate local fixture CLI using the same trusted database configuration, not a paid/live HTTP endpoint. Unknown options/targets/modes fail before execution. The existing HTTP API remains mock submission only, with readable history after migration. No arbitrary target path, image, command, endpoint, provider key or model override is accepted from specs/CLI.
- Check ownership before stage dispatch and immediately before worker start; propagate owner loss/cancellation/deadline into active workers. Under the new owner's lock, remove only strictly named/labeled abandoned ForgeTS containers before admitting new fixture work. Prove cancellation/owner-loss behavior, startup cleanup and unchanged source data with disposable resources; report cleanup uncertainty without pretending a terminal record is durable.
- Supply a minimal locked NestJS sample as a trusted development fixture and check its identity against the in-memory snapshot. Demonstrate one real Docker edit through the fake provider and PostgreSQL, reload records/events and inspect actual hashes/diff. Preserve historical M1 mode/provenance after migration/restart. Test rejected malicious outputs before success; no generated-code checks run on the host.
- Run `npm run verify`, existing database regressions, the new durable workflow integration and worker containment tests. Record observed counts and limitations; commit the spec/implementation/tests/evidence only after passing. A live run remains unverified and the full M2 milestone incomplete unless the human explicitly accepts an adjusted completion scope. Stop before M3.
