# ADR 0012: Offline immutable tools and bounded verification

- Date: 2026-11-10
- Status: implementation decision recorded before execution code under explicit M3 authorization; milestone review pending

The human instructed continuation to M3 after the M2 review handoff. This authorizes offline verification/repair work without claiming M2's unperformed live run passed. Paid calls remain blocked. M3 depends on unmerged M2 commits, so use a stacked local branch from the accepted M2 snapshot; preserve `master` and all history without merging or remote access.

Prepare one local image from the approved pinned Node base and exact installed locked dependencies. Bootstrap copies only bounded regular files belonging to lockfile package paths plus fixed compiler/linter/test assets into an owned build directory. Skip workspace links and reject filesystem links/unsupported objects; include no target source, credentials, npm config or host mounts. The Dockerfile has COPY only, no RUN/install hooks, and build network is disabled. Record the observed image ID/content fingerprint in ignored local bootstrap metadata. This metadata is trusted operator configuration, never model/spec/worker input; runtime verifies the selected immutable image and its labels. Rebuild after clean dependency installation when tool bytes change. Installed dependencies and Docker remain trusted supply-chain inputs, not proven safe software.

Each check uses a fresh container, retaining M2's default seccomp, no network/capabilities/privilege escalation/host mounts and uid 1000. M3 raises limits to 512 MiB/no additional swap, one CPU, 64 PIDs and 64 MiB tmpfs because real compiler/linter processes need more memory than byte replacement. The tools/configuration/tests are in the read-only image. A trusted worker materializes validated source and a fixed package/compiler setup; its workspace node_modules link points only at immutable image tools. Model-provided paths cannot select that link or a host path. No generated dependency manifest, config file, install hook or command is accepted.

Registry order is format, lint, typecheck, test. Use explicit Node executable/script paths and arguments, never a shell. The test check recompiles in its own fresh workspace before running an immutable greeting assertion. Required checks cannot be skipped or reused across digests. Child execution is limited to eight seconds; attached worker time to twelve seconds; Docker control commands to fifteen seconds. Whole repair orchestration will have a 180-second logical deadline plus bounded cleanup (up to 45 additional seconds during a failing control operation). At most two repairs and three full verification rounds; no provider retries. A malformed/failed repair consumes its attempt and terminates rather than receiving a free retry.

Capture separate stdout/stderr up to 512 bytes each. Overflow kills the check and marks failure/truncation. Record real exit/signal/flags and timing; missing results cannot pass. Kill the process group on timeout/output overflow, then remove the entire container so detached descendants cannot survive a completed check. Failed Docker cleanup blocks further work. Common bearer/API-key/URL-credential patterns are redacted before persistence; this is not a universal secret scanner. The container never receives provider/database keys.

A fixed sample assertion establishes only that tested greeting behavior and static gates passed; it does not prove arbitrary correctness/security or grant approval. M3 success ends at a verified-awaiting-review checkpoint for M4, not merge readiness. Development token/account quota figures remain unavailable; fake repair usage must be identified separately.
